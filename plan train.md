# План: обучить быстрый детектор iris + pupil на 1600 фото

## Context (зачем)

Текущий пайплайн (`iris_cut.py`) находит iris/pupil через SAM ViT-B + MediaPipe + 3 тира эвристик.
Это надёжно, но **медленно и тяжело по VRAM** (~3 ГБ, LaMa, секунды на кадр). У вас есть
~1600 фото глаза (белые люди из РФ) и ручная разметка в формате `jsonOutputs/*.json`
(окружности iris и pupil в пикселях оригинала, плюс случаи «нет глаза»). Цель этого этапа —
**обучить отдельную лёгкую нейросеть-детектор**, которая по фото за миллисекунды выдаёт те же
`(cx, cy, r)` для iris и pupil. Интеграцию в `iris_cut`/`iris_server` делаем **позже** —
сейчас нужны только обученные веса + метрики.

Решения, согласованные с пользователем:
- **Модель:** YOLO11 (Ultralytics), детекция 2 классов (iris, pupil) как окружности → bbox.
- **Цель этапа:** только обучить веса и получить метрики (интеграция позже). ONNX-экспорт делаем
  попутно «бесплатно» — пригодится.
- **Данные:** разметка ещё идёт (часть выверена в `json_editor.py`) — план учитывает дозаливку
  и фиксированный held-out тест.
- **Железо для обучения:** RTX 3070 12 ГБ (не 2070). Запаса VRAM достаточно для `yolo11m@1280`
  (batch ~12-16) или `yolo11s@1536` — это даёт лучшие метрики, особенно по мелкому pupil.

Обучение пойдёт в **отдельном проекте Claude Code**; ниже — готовый промпт для него.

## Ответ на вопрос «нужен ли тестовый набор?»

**Да, обязательно.** Делим на три части:
- **test (~10%, ≈160 фото)** — заморозить в самом начале и больше не трогать; финальная честная оценка.
- **val (~15%)** — для отбора чекпойнтов и ранней остановки во время обучения.
- **train (~75%)** — обучение; этот набор может расти по мере дозаливки разметки.

**Важно — защита от утечки между почти-дубликатами.** Фото сняты всего за ~4 дня, поэтому
деление по датам не работает (всего ~4 группы — слишком крупно). Повторения одного человека
встречаются **только у соседних по id кадров**. Значит правильный сплит — **непрерывными блоками
id с буфером на стыках**:
- Сортируем все кадры по числовому id.
- Режем на непрерывные диапазоны: например первые ~75% id → train, следующие ~15% → val,
  последние ~10% → test (или test берём непрерывным блоком в середине — главное, чтобы он был
  одним сплошным диапазоном id).
- На **каждом стыке** выбрасываем (не используем) буфер из нескольких соседних кадров — например
  3-5 id с каждой стороны границы, — чтобы один и тот же человек не оказался по обе стороны.
- Кадры «нет глаза» остаются на своих id внутри блоков (распределятся естественно); следить,
  чтобы их доля в test была ненулевой.

Так соседние почти-дубликаты гарантированно лежат в одном наборе, а граничные потенциальные
повторы отрезаны буфером. test после нарезки — заморозить.

## Подход (почему именно так)

YOLO11 — лучший баланс «скорость / устойчивость / зрелость тулинга» для 1600 фото на RTX 2070:
- Находит глаз **в любом месте кадра** (портреты, пол-лица, макро) — это снимает проблему
  локализации, на которой спотыкается прямая регрессия.
- Очень быстрый инференс, тривиальный экспорт в ONNX (под TouchDesigner/onnxruntime позже).
- Окружность ↔ bbox — взаимно-однозначно: `bbox = (cx, cy, w=2r, h=2r)`; на инференсе обратно
  `cx,cy = центр bbox`, `r = (w+h)/4`. pupil концентричен внутри iris — YOLO спокойно держит
  перекрывающиеся боксы разных классов.

### Ключевой технический риск: маленький зрачок на большом кадре
Фото ~5760×3240, iris r≈210, **pupil r≈32**. При обучении YOLO ужимает вход до `imgsz`.
- При `imgsz=1280`: iris-бокс ≈47 px (ок), pupil-бокс ≈14 px (на грани, но детектируемо).
- Рекомендация под RTX 3070 12 ГБ: **`yolo11m.pt` при `imgsz=1280`, batch≈12** (или
  `yolo11s.pt` при `imgsz=1536`, batch≈12) — больше модель/разрешение лучше ловят мелкий pupil.
  При нехватке VRAM → снизить batch или imgsz=1024.
- Если recall по pupil окажется низким: поднять `imgsz` до 1536, либо обучить **только iris** YOLO,
  а pupil доставать на кропе iris (вторая мини-стадия или классический `_detect_pupil_in_iris`).
  Это запасной путь, не делаем сразу.

## Что сделает отдельный проект (этапы)

1. **Конвертер `json → YOLO`** (`tools/json_to_yolo.py`):
   читает каждый `jsonOutputs/<stem>.json` + соседнее исходное фото; на успех пишет
   `labels/<stem>.txt` со строками `class cx/W cy/H (2r)/W (2r)/H` (нормированные 0..1),
   класс `0=iris`, `1=pupil`; на «нет глаза» (`success:false`) — **пустой** `.txt`
   (YOLO трактует как background-кадр). Берёт `W,H` из `source.width/height` (а не из файла) —
   совпадает с координатной системой меток. Чтение картинок — unicode-safe
   (`np.fromfile` + `cv2.imdecode`), как в репозитории.

2. **Блочный сплит по id с буфером** (`tools/make_split.py`):
   сортирует кадры по числовому id, режет на непрерывные диапазоны train/val/test, выбрасывает
   буфер из 3-5 id на каждом стыке (защита от соседних дубликатов), раскладывает в
   `dataset/{train,val,test}/{images,labels}`, замораживает test, пишет `data.yaml`
   (`names: [iris, pupil]`, пути, `nc: 2`). Логировать границы блоков и список отброшенных id.

3. **Обучение** (RTX 3070 12 ГБ): `yolo detect train model=yolo11m.pt data=data.yaml imgsz=1280
   epochs=100 batch=12 patience=20 device=0`. Логи/чекпойнты в `runs/`.

4. **Оценка на test**: `yolo detect val ... split=test` → mAP50/mAP50-95, precision/recall
   **по каждому классу отдельно** (pupil будет слабее iris). Плюс прикладная метрика:
   средняя ошибка центра (px) и радиуса (px/%) на test — ближе к реальной задаче, чем mAP.

5. **(Попутно) ONNX-экспорт**: `yolo export model=runs/.../best.pt format=onnx imgsz=1280`.

6. **Deliverables**: `best.pt`, `best.onnx`, `data.yaml`, отчёт с метриками и парой
   визуализаций предсказаний на test.

## Verification (как убедиться, что всё работает)

В отдельном проекте, по порядку:
1. После конвертера — глазами проверить 3-4 `_debug`-наложения против сгенерённых `.txt`
   (нарисовать bbox по `.txt` поверх фото; центры и радиусы должны совпадать с окружностями).
2. После сплита — убедиться, что диапазоны id наборов не пересекаются, на стыках есть буфер
   из отброшенных id; проверить число фото и долю «нет глаза» в каждом наборе (в test > 0).
3. После обучения — `yolo detect val split=test`; целевой ориентир: iris mAP50 > 0.9;
   pupil слабее — смотреть на прикладную ошибку центра/радиуса.
4. Визуально — 5-10 предсказаний на **test** поверх фото: iris и pupil концентричны и совпадают
   с глазом.
5. ONNX — прогнать один кадр через onnxruntime и сверить с `best.pt` (совпадение в пределах
   нескольких пикселей).
